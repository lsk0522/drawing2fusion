# dxf-reading.md — DXF 도면 읽기

`python -m d2f run 도면.dxf` (또는 `run.bat`에 끌어다 놓기)가 하는 일과, 잘 읽히는 도면을 그리는 법.

## 1. 처리 순서

```
DXF ─▶ ① 정리 ─▶ ② 뷰 나누기 ─▶ ③ 뷰 이름 붙이기 ─▶ ④ 치수 확인 ─▶ ⑤ 형상 추론 ─▶ part-spec.json
          │            │                │                  │                 │
   테두리·표제란 제외  선이 닿거나 안에   정면/평면/측면,     치수 문자 vs     높이 구간별 돌출 +
                      들어간 것끼리 묶기  제3각·제1각 판별    그려진 길이       구멍 / 카운터보어
```

1. **정리** — `TITLE / BORDER / FRAME / 표제 / 윤곽` 같은 이름의 레이어, 전체를 감싸면서 안에 표제란 글자(SCALE, 척도, 도명 …)가 있는 사각형, 그 글자를 담은 표제란 칸을 지웁니다.
2. **뷰 나누기** — 실선·숨은선을 서로 닿거나 겹치는 것끼리 묶고, 다른 묶음 안에 들어간 묶음(구멍 원 등)은 그 뷰에 합칩니다. 중심선은 묶을 때 쓰지 않습니다.
3. **뷰 이름** — 폭이 같은 뷰끼리(정면↔평면), 높이가 같은 뷰끼리(정면↔측면) 짝을 짓습니다. 평면도가 정면도 **위에** 있으면 제3각법(KS 기본), **아래**면 제1각법입니다. 도면에 `1ST ANGLE` / `제1각법` 글자가 있으면 제1각법으로 봅니다. 뷰가 하나면 평면도로 보고 두께는 주기(`t=5`, `T6`)에서 읽습니다.
4. **치수 확인** — DIMENSION마다 정의점 사이의 실제 길이와 표시된 문자를 비교합니다.
   - 문자가 `<>`(자동)면 그대로 사용
   - 손으로 고친 문자가 실제 길이와 다르면 **E107 질문**: 그려진 값 / 치수 문자 값 / 직접 입력
   - 모든 치수 문자가 같은 비율로 다르면 축척 도면으로 보고 그 비율을 곱합니다 (예: 1:2)
5. **형상 추론**
   - 정면도의 수평 실선으로 **높이 구간(층)**을 나눕니다.
   - 맨 아래 층이 전체 폭이면 평면도 외곽(사각형 / 모서리 R 사각형 / 원 / 직선 다각형)을 돌출합니다.
   - 위 층은 같은 폭의 평면도 원이 있으면 원기둥, 없으면 정면·측면도 폭으로 만든 사각 블록입니다.
   - 평면도의 원은 구멍이 됩니다. 같은 중심의 원 두 개는 카운터보어로 봅니다. 깊이는 정면도 숨은선의 길이로 정하고, 숨은선이 없으면 관통으로 가정하면서 경고합니다. 카운터보어 깊이는 `DP5.4`, `깊이 5.4`, `↧5.4` 주기에서 읽습니다.
   - 치수가 없는 값은 가능하면 식으로 잇고(`H = h1 + h2`, `h2 = H - h1`, 원형이면 `W = L`), 안 되면 "치수 없음 – 형상에서 잼"으로 표시합니다(경고).

## 1-1. 회전체 단면도 (해칭이 있을 때 먼저 시도)

해칭(HATCH)이 있으면 투상도 해석 전에 **회전체 반단면**인지 먼저 봅니다 (`d2f/extract/section_reader.py`).

1. **축 찾기** — 중심선(가로 또는 세로)을 기준으로 해칭 경계가 양쪽에 거울처럼 있는지 확인. 바깥 범위(축 방향 길이, 최대 반지름)가 양쪽에서 같아야 합니다. 한쪽에만 있는 해칭(플랜지 판의 부분 단면 등)은 회전체가 아니라고 보고 기존 E208 질문으로 갑니다.
2. **단면 뷰 모으기** — 구멍이 위아래 반쪽을 갈라 놓아 뷰가 두 덩어리로 나뉘어도, 해칭 영역에 걸친 뷰는 모두 한 단면으로 합칩니다.
3. **재료 프로파일** — 해칭 경계 + 해칭 바깥쪽에 붙은 *해칭 안 된 닫힌 영역*(기어 이, 리브는 관례상 해칭하지 않음)을 합칩니다. 해칭보다 축 쪽에 있는 빈 영역(키홈 띠, 구멍)은 재료로 넣지 않습니다.
4. **어느 쪽 반을 쓸지** — 안쪽 반지름이 더 작은 쪽(구멍이 온전한 쪽)이 프로파일. 반대쪽 안쪽 선이 더 높으면 그 높이까지 **키홈**이 단면을 지나는 것으로 보고, 끝 모양(원 위의 홈)에서 폭을 읽습니다. 끝 모양이 없으면 폭을 묻습니다(E202).
5. **치수 연결** — 축 방향 좌표는 기준면(X=0)에서 잰 치수(치수 보조선 위치까지 확인), 그다음 이미 아는 위치에서 이어 잰 **연쇄 치수**(`10` + `40`), 모따기 `1.5x45°`. 반지름은 지름 치수(`Ø`), 지시선 글자(`ø35 H6`). 치수가 없는 꼭짓점은 30/45/60° 경사 연장으로 식을 만들고(INFO), 그래도 없으면 형상에서 잰 값(WARN).
6. **작은 작도 오차** — 치수 문자와 그려진 길이가 max(0.05 mm, 0.3%) 이내로 다르면 작도 오차로 보고 **치수 문자 값**을 씁니다(INFO). 그보다 크면 E107 질문. (투상도 경로도 같은 규칙)
7. **검사** — bbox, 구멍 지름·위치(X축), 키홈 바닥 `plane`, Pappus 부피(− 키홈), 그리고 도면 선에서 직접 만든 측면 실루엣(E406).

## 1-2. 옆 구멍 · 탭 · 공차 (v0.3)

- **옆 구멍:** 정면도의 원 = Y 방향 구멍, 측면도의 원 = X 방향 구멍. 깊이는 다른 뷰의 숨은선(평면도의 세로·가로 숨은선,
  없으면 측면/정면도)으로 정하고, 숨은선이 한쪽 면에서 시작하면 그 면에서 뚫은 막힌 구멍(`DP25` 주기와 대조), 양쪽 면까지면 관통.
- **탭:** `M6`, `4-M6`, `M8x1.25` 글자가 구멍 가까이(개수가 있으면 가까운 순서로 그 개수만큼) 있고, 원이 탭 드릴(호칭−피치)이나
  호칭 지름이면 나사 구멍. 굵은 원 + 가는 3/4 원호(ISO 그리기)에서 큰 원을 카운터보어로 오해하지 않습니다. 피치 없으면 보통 나사.
- **공차:** `31.83±0.1`, `38.3 +0.2/0`(쌓은 글자), `Ø35 H6`, `Ø97.66 h11`, `10 P9` → 파라미터 `tolerance`/`fit` (ISO 286 표 내장).

## 2. 파라미터 출처 표시 (`source.type`)

| 값 | 뜻 | 빌드 |
|---|---|---|
| `drawing` | 도면 치수에서 읽음 (`label`에 치수 문자) | 그대로 |
| `derived` | 다른 치수로 계산한 식 | 그대로 |
| `inferred` | 치수 없이 그려진 형상에서 잰 값 | 경고(E207) 후 진행 |
| `conflict` | 치수 문자 ≠ 그려진 형상 | **질문(E107)** |
| `unresolved` | 알 수 없음 (예: 1면도에 두께 주기 없음) | **질문(E202)** |
| `user` | 질문에 답한 값 (`previous`에 원래 출처) | 그대로 |

## 3. 잘 읽히는 도면 그리기

- 실제 크기(1:1)로 그리고 단위는 mm (`$INSUNITS = 4`)
- 숨은선은 `HIDDEN`/`DASHED` 선 종류나 레이어, 중심선은 `CENTER` 선 종류나 레이어
- 테두리와 표제란은 `TITLE` 같은 별도 레이어
- 치수는 DIMENSION 객체로 (선 + 문자로 쪼개진 치수는 못 읽음), 문자 덮어쓰기는 피하기
- 구멍 수량은 `4-Ø6.6`, 카운터보어는 `C'BORE Ø9.5 DP5.4`처럼

## 3-1. 곡선·경사 외곽 (`d2f/extract/intersect.py`)

| 도면 | 만드는 방법 |
|---|---|
| 평면도 외곽에만 호 (둥근 끝 링크, 둥근 모서리가 섞인 판) | 층 방식 그대로, 외곽을 다각형 근사 대신 선·호 `path`로 정확히 스케치 (부피 정확) |
| 정면도·측면도 외곽에 호나 경사선 (둥근 머리 러그, 경사면 블록) | **투상도 교차**: 각 뷰의 바깥 외곽을 그 뷰 방향으로 돌출해 교차 — 정면(XZ)→Y로 W, 평면(XY)→Z로 H, 측면(YZ)→X로 L. 전체 사각형인 뷰는 건너뜀 |

- 외곽 꼭짓점 좌표가 원점에서 잰 치수와 같으면 파라미터(`f_u1` 등, 출처 = 그 치수), 전체 크기와 같으면 `L/W/H`
- 외곽 호의 반지름 치수(`R25`)는 `f_r1` 같은 파라미터로 기록하고 스케치 반지름 치수가 그 파라미터를 씀
- 위 구멍은 구멍 자리에서 가장 높은 면부터 아래로 (경사면 위 구멍도 덜 뚫리지 않게), 부피는 구멍 중심의 재료 높이로 계산
- 부피 기대값: 돌출이 하나면 정확한 면적 × 깊이, 둘 이상이면 세 외곽 교차를 격자 적분(오차 ~0.03%)
- 검증: 도면 선에서 만든 실루엣(E406)이 따로 대조하므로, 교차 방식이 맞지 않는 부품이면 실루엣 검사가 잡음

## 4. 아직 못 읽는 것

- 상세도, 옆 구멍의 카운터보어, 비스듬한 구멍
- 곡선·경사 외곽은 이제 읽음 (아래 "곡선·경사 외곽") — 단, 정면도 외곽이 곡선이면서 **높이 층마다 평면 외곽이 다른** 부품(곡선 포크 + 가는 원기둥 축 같은 회전체 혼합)은 아직 층 방식 근사 + WARN
- 회전체가 아닌 단면도(판의 부분 단면, 리브 단면 등) — E208 질문으로 멈춤. 축 방향 키홈이 아닌 홈(멈춤 키홈, 가로 구멍)
- 회전체 단면도의 나사·널링·치형은 블랭크까지만 (주기로 기록)
- 등각도(입체도)는 참고용으로 빼고 INFO, 작도선 레이어(`aux`, `construction`, `defpoints`, `보조`)와 XLINE/RAY는 무시
- 기하공차·표면 거칠기(주기로 기록만 함), 인치 나사(UNC 등)
- 블록(INSERT) 안에 뷰 전체가 들어간 도면은 펼쳐서 읽지만 블록 이름으로 뷰를 판단하지는 않음
- 시험한 도면: `tools/make_sample_dxf.py`로 만든 12장(회전체 단면 5장 포함) + 공개 도면 3장 — 전부 `tools/regress.py`로 Fusion에서 회귀 테스트 ([verification-sections-regression.md](verification-sections-regression.md))

## 5. 결과 파일

- `out/<이름>/part-spec.json` — 해석 결과(사람이 고쳐서 다시 `d2f build` 가능)
- `out/<이름>/extract-report.json` — 뷰 위치, 투상법, 축척, 치수마다 실제 길이·문자·불일치 여부
- `notes`에 "미사용 치수" 목록 — 자동 해석에 안 쓴 치수(구멍 위치 등). 모델 검증 때 확인용
