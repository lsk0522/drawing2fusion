## 2. 🔴 꼭 필요한 기능 (Must)

### 2.1 판독값 신뢰도 3단계 표시
- **내용:** 모든 치수·피처를 `drawing`(도면에 명시) / `inferred`(추론) / `unresolved`(미해결)로 분류해서 색으로 표시
  - 초록 = 도면 근거, 주황 = 추론, 빨강 = 미해결
- **왜:** 상용 서비스들이 공통으로 갖춘 기능. 사용자가 어디를 확인해야 하는지 바로 알 수 있음
- **구현:** `part-spec.json`의 `source.type`에 `unresolved` 추가. 리포트·팔레트·알림 전부 같은 색 규칙 사용
- **참고:** Voluminate(도면 근거/추론/미해결 분류), Drawing Agent(저신뢰 영역 주황 표시)

### 2.2 실측 기반 치수 검증
- **내용:** 완성 바디에서 구멍 지름, 면 간 거리, 바운딩 박스를 직접 측정해서 도면 값과 mm 단위로 비교
- **왜:** 경쟁 서비스들은 주로 렌더 이미지 비교로 검증함. **수치로 증명하는 검증이 우리의 핵심 차별점**
- **구현:** `docs/architecture.md` 2.5 Verifier 그대로

### 2.3 재실행 가능한 기록
- **내용:** 판독 결과(JSON) + 빌드 로그 + 검증 리포트를 모두 남겨서, 누가 봐도 왜 이 모델이 나왔는지 추적 가능
- **참고:** Drawing Agent는 `cad_ir.json`(치수·연산 정보)과 생성 코드를 함께 납품함 → 우리 `part-spec.json` 방향과 같음

### 2.4 사람 확인 단계
- **내용:** 검증 리포트의 각 항목에 사용자가 OK / NG 체크. NG 항목은 수정 후 해당 피처만 재빌드
- **왜:** 상용 서비스도 전부 "AI 결과는 후보일 뿐, 최종 승인은 사람"이라는 입장. 공차·GD&T·재질은 특히 사람 검토 필요
- **구현:** `report.html`과 팔레트에 체크박스. 결과는 `review.json`으로 저장

### 2.5 모바일 알림 + 버튼 응답
- **내용:** 오류·불일치·질문을 휴대폰으로 받고, 버튼으로 답하면 빌드가 이어짐
- **왜:** 조사한 서비스 중 실시간으로 묻고 이어가는 방식은 없음 → 차별점
- **구현:** Telegram 봇 인라인 버튼 우선 (`docs/errors-and-alerts.md` 4장)

## 3. 🟡 배워야 할 기능 (Learn)

### 3.1 렌더 비교 자동 수정 루프
- **어디서:** Drawing Agent — 8방향 + 단면 렌더를 도면과 비교해 점수화, 목표 미달 시 파라미터 수정, 최대 10회 반복
- **어디서:** cad3dify — 코드 생성 → 실행·디버그 → STEP → 렌더 → 수정 에이전트
- **우리 방식:** 실측 검증(2.2)을 1차로, 렌더 비교를 2차 보조로. 수정은 스펙(JSON)만 바꾸고 빌더는 그대로 → 결정성 유지
- **주의:** 반복 횟수 상한과 "점수가 안 오르면 멈추고 사용자에게 묻기" 규칙 필수

### 3.2 해석 후보 여러 개
- **어디서:** Voluminate — 후보 최대 3개를 순위와 함께 제시
- **우리 방식:** 2D → 3D 해석이 갈리면(E208) 후보별 스냅샷을 만들어 팔레트·휴대폰에서 선택

### 3.3 도면 + 사진 함께 입력
- **어디서:** Voluminate — PDF와 실물 사진을 같이 넣을 수 있음
- **우리 방식:** 사진은 형상 판단(관통 여부, 숨은 형상)의 보조 근거로만 사용, 치수는 도면 우선

### 3.4 단면 렌더 비교
- **어디서:** Drawing Agent — 외형 8방향과 별도로 단면 렌더도 비교
- **우리 방식:** 도면에 단면도가 있으면 같은 위치를 Fusion에서 단면 분석해 비교

### 3.5 참고만 할 것 (지금 범위 밖)
- 어셈블리 분해, CAE 간이 해석 (Drawing Agent)
- 엔지니어 검수 유료 등급 구조 (Voluminate)
- 온프레미스 배포, 보안 인증 (Aibuild, Drawing Agent) — 기업용 단계에서나 의미 있음

## 4. 🟢 그대로 활용할 것 (Use)

| 대상 | 활용 방법 | 비고 |

| Werk24 API | 래스터 도면에서 치수·공차·GD&T·표제란을 읽어 Claude 판독값과 교차검증 | 유료 API일 가능성. Phase 4에서 비용 확인 후 선택 |
| cad3dify | 루프 구조와 프롬프트 설계 참고 | 작성자가 후속작 agent3dify를 권장 |

## 5. 우리만의 차별점 (유지해야 할 것)

1. **Fusion 피처 트리가 남는 파라메트릭 모델** — 대부분 STEP 납품이라 수정 이력이 없음. Voluminate도 피처 트리는 엔지니어가 다시 만드는 최상위 등급에서만 제공
2. **mm 단위 실측 검증** — 렌더 비교가 아니라 수치로 증명
3. **실시간 질문·알림** — 모르면 멈추고 묻고, 휴대폰으로 답하면 이어서 진행
4. **로컬·개인 사용** — 무료, 도면이 외부 서비스에 쌓이지 않음 (Claude API 호출 제외)

## 7. UI/UX 정리

### Fusion 팔레트 (메인)
- **해석 확인 화면:** 도면 위에 판독 치수 색상 오버레이(2.1), 탭하면 수정
- **진행 화면:** 피처 목록 타임라인, 단계별 체크
- **라이브 빌드 모드:** 열린 Fusion 창에서 피처가 하나씩 생기는 걸 그대로 보여줌. 피처 사이 지연(예: 0.5초)과 카메라 자동 맞춤 옵션, 일시정지·한 단계씩 진행 버튼. 완료 후 `.f3d` 저장 + 필요 시 `.step`/`.stl` 내보내기
- **검증 화면:** 도면 뷰 ↔ 모델 스냅샷 나란히 + 치수 비교표. 행을 누르면 모델 면 하이라이트 + 도면 위치 확대
- **후보 선택 화면:** 해석 후보 2~3개 스냅샷 비교(3.2)

### 휴대폰 (Telegram 봇 우선)
- 알림은 결과 한 줄 먼저: `❌ 구멍 Ø6.6 → 실측 6.0`, 상세는 펼쳐 보기
- 질문은 버튼 카드로 하나씩
- 완료 시 통과/경고 개수 요약 + 리포트 링크

### UX 원칙
- 질문은 모아서 한 번에 받기 (빌드 도중 계속 끊지 않기)
- 실패하면 해당 피처만 고쳐서 재빌드
- 모든 값에 "왜 이 값?" → 도면 어디서 읽었는지 보여주기
- 색 규칙(초록/주황/빨강)은 모든 화면·알림·리포트에서 통일
