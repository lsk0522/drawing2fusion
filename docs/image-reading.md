# image-reading.md — 채팅으로 도면 판독하기 (API 키 없이)

사진·스크린샷·PDF처럼 **DXF 리더가 못 읽는 도면**, 또는 DXF라도 단면도·회전체처럼 자동 해석이 멈추는 도면을
Claude와 대화하면서 Fusion 모델로 만드는 절차입니다. 판독은 채팅 안의 Claude가 하고, 나머지(검증 → 빌드 →
실측 → 알림 → 비교 이미지)는 같은 파이프라인(`run.bat`)으로 돌립니다.

> 왜 이 방식인가: 이미지 자동 판독(Phase 4)을 코드로 넣으려면 Anthropic API 키(유료)가 필요합니다.
> 채팅 판독은 키 없이 같은 결과(스펙)를 만들고, 사람이 판독 과정을 보면서 바로 답할 수 있다는 장점이 있습니다.
> 나중에 자동 판독기를 넣어도 **출력 형식(part-spec.json)은 그대로**입니다.

## 1. 한눈에

```
① 도면 보내기 ─▶ ② 판독표 ─▶ ③ 질문 (애매한 것만) ─▶ ④ 스펙 작성 ─▶ ⑤ validate
      ─▶ ⑥ PC로 보내기 ─▶ ⑦ run.bat 빌드·검증 ─▶ ⑧ 비교 이미지 ─▶ ⑨ 고치기 / 완료
```

| 단계 | 누가 | 결과 |
|---|---|---|
| ① 도면 보내기 | 사용자 | 채팅에 사진/스크린샷/PDF 첨부 (한 장에 여러 뷰면 그대로) |
| ② 판독표 | Claude | 뷰 목록, 치수 목록(값·공차·위치), 형상 해석, **검산 결과** |
| ③ 질문 | Claude → 사용자 | 도면만으로 정할 수 없는 것만 (깊이 미표기, 숨은선 의미 등). 없으면 건너뜀 |
| ④ 스펙 | Claude | `samples/specs/<이름>.json` — 출처(`source`)와 `notes` 포함 |
| ⑤ validate | Claude | `python -m d2f validate <spec>` → ERROR/BLOCK 0 |
| ⑥ 보내기 | Claude | PC가 연결돼 있으면 스펙·도면 이미지를 프로젝트 폴더에 저장 |
| ⑦ 빌드 | Claude (또는 사용자: `run.bat`에 스펙 끌어다 놓기) | Fusion 모델 + `out/<이름>/verify-report.json` |
| ⑧ 비교 | Claude | `py -3 tools\compare_image.py <도면> out\<이름>` → `compare.png` |
| ⑨ 마무리 | 둘 다 | 틀린 곳은 스펙만 고쳐 다시 ⑦. 끝나면 f3d / STEP |

PC가 연결되지 않은 상태면 ①~⑤까지 하고 스펙 파일을 채팅으로 보냅니다. 사용자가 `run.bat`에 끌어다 놓으면 ⑦부터 같습니다.

## 2. 판독 규칙 (Claude가 지키는 것)

### 2.1 좌표와 기준 정하기
- 스펙 좌표는 **월드 축**입니다: X = 정면도 가로, Y = 깊이, Z = 높이. 스케치 평면 `XZ` → (X, Z), `YZ` → (Y, Z)
- 원점은 도면의 **치수 기준**(데이텀, 대칭축, 회전축)에 둡니다. 치수 대부분이 그 점에서 바로 읽히도록
- 회전체: 축 = X, 반단면 프로파일을 `XZ` 평면에 그리고(가로 = 축 방향, 세로 = 반지름) `revolve`
- 투상법 확인: 평면도가 정면도 위 = 제3각, 아래 = 제1각. 기호나 `1ST ANGLE` 글자가 있으면 그걸 따름

### 2.2 치수마다 출처 기록
| 경우 | `source.type` | 예 |
|---|---|---|
| 도면에 적힌 값 | `drawing` (+`label` 원문, `confidence`) | `"label": "Ø97.66 h11"` |
| 다른 치수로 계산 | `derived` (+`reason`, 값은 식) | `"value": "x_heel - (d_tip - d_hub)/2"` |
| 그림에서 잰 값·가정 | `inferred` (+`reason`) → 경고 | 깊이 미표기 → 관통 가정 |
| 사용자가 답한 값 | `user` | ③ 질문의 답 |

공차(`H6`, `±0.1`, `+0.2/0`)는 `tolerance`에, 참고치수 `(18)`은 `derived` 파라미터와 대조하는 데 씁니다.

### 2.3 검산 — 판독이 맞는지 치수끼리 확인
한 치수를 두 가지 길로 구할 수 있으면 반드시 맞춰 봅니다. 안 맞으면 스펙을 만들기 전에 질문합니다.
- 참고치수 `( )`와 계산값 (예: 베벨기어 `(18)` = 31.83 − (97.66 − 70)/2 = 18.0 ✔)
- 경사 길이와 좌표 차이 (예: 이폭 16 = √(10.6² + 12.01²) = 16.02 ✔)
- 전체 치수 = 부분 치수의 합, 뷰 사이 폭·높이 일치
- 픽셀 비율: 그림 위 길이 ÷ 치수가 모든 치수에서 비슷한지 (휴대폰 사진은 ±5% 정도 허용)

### 2.4 질문할 것 / 하지 않을 것
- **질문:** 같은 도면을 두 가지로 해석할 수 있고, 그 차이가 모델을 바꾸는 것 (구멍 관통 여부, 숨은선이 무엇인지)
- **질문 안 함:** 일반적인 관례로 정해지는 것 → 가정하고 `inferred` + `notes`에 기록
  (예: 깊이 없는 드릴 = 관통, 표시 없는 모서리 = 날카로움)
- 모델에 넣지 못하는 것(치형, 나사, 거칠기, 기하공차)은 `notes`에 `"applied": false`와 이유

### 2.5 검사(`checks`) 고르기
| 형상 | 넣을 검사 |
|---|---|
| 모든 부품 | `bbox` (전체 크기) |
| 구멍 | `hole_count`, `hole_diameter`, `hole_positions` (`axis` 지정) |
| 회전체·단순 형상 | `volume` — 계산할 수 있으면 기대값 + `rel_tol` (Pappus: 2π × 단면적 × 도심 반지름) |
| **방향이 중요한 형상** (키홈, 한쪽 포켓, 비대칭 리브) | `plane` — 그 면이 있어야 할 좌표. **bbox·부피가 같아도 반대쪽에 만들어진 실수를 잡는 유일한 검사** |

## 3. 명령 모음 (Windows, 프로젝트 폴더에서)

```bat
:: 스펙 검사만
py -3 -m d2f validate samples\specs\<이름>.json

:: 빌드 + 검증 + 스냅샷 + f3d  (run.bat에 끌어다 놓기와 같음)
run.bat samples\specs\<이름>.json

:: 이미 열린 모델만 다시 재기
py -3 -m d2f verify samples\specs\<이름>.json --no-snapshot --export ""

:: 비교 이미지 (휴대폰 캡처 여백은 자동으로 잘림, 직접 자르려면 --crop x0,y0,x1,y1)
py -3 tools\compare_image.py samples\drawings\images\<도면>.png out\<이름>
```

## 4. 결과물

- `samples/specs/<이름>.json` — 판독 결과 (다시 쓸 수 있는 원본)
- `samples/drawings/images/<도면>.png` — 원본 도면 사본
- `out/<이름>/` — `<이름>.f3d`, `verify-report.json`, `snapshots/*.png`, **`compare.png`**

## 5. 실제로 해 본 것

| 도면 | 종류 | 결과 | 기록 |
|---|---|---|---|
| 클램프 브래킷 (휴대폰 캡처) | 제3각 2면도, 구멍·카운터보어·리브·슬릿 | 13/13 | [verification-image-test.md](verification-image-test.md) |
| 베벨기어 블랭크 (QCAD 예제 DXF → 이미지) | 단면도 + 키홈 측면도, 공차 | 7/7, 부피 오차 0.0000% | [verification-public-drawings.md](verification-public-drawings.md) |

베벨기어에서 판독 실수 하나(키홈을 −Y 쪽에 만듦)가 bbox·부피 검사를 모두 통과했고 비교 이미지에서만 보였습니다.
그래서 `plane` 검사(E408)를 추가했고, 같은 잘못된 모델에 다시 돌리면 이제 E408로 멈춥니다.
